# Top-Down 쿼리 작성법

## 1단계
- 최종 출력될 표의 한 행이 무엇을 의미하는지 정리하기.
- 메인 쿼리의 `SELECT` 와 `GROUP BY` 절이 확정된다.
- 이 작업으로 메인 쿼리의 뼈대가 세워진다.

## 2단계
- 문제의 조건들을 평가해 필터링을 어느 시점, 어느 위치에서 수행할지 결정하기.
  - 단순히 날짜나 상태값이 A인 것만 필요하다면 -> 메인 쿼리의 `WHERE`절
  - 특정 조건을 만족하는 대상의 목록을 뽑아야한다면 -> 메인 쿼리의 `WHERE 컬럼 IN (서브쿼리)`
  - 기존 테이블에 없는 완전히 새로운 통계 컬럼이 필요하고 그 값을 다른 테이블과 JOIN 하거나 조건식에 복합적을 사용해야한다면 
-> 메인 쿼리의 `FROM (서브쿼리) 또는 CTE(WITH절)`

## 3단계
- 설계가 끝나면 쿼리 실행 순서에 따라 블록 조립하기.
- `SELECT` 의 비집계 컬럼이 `GROUP BY` 절에 모두 있는지 등등 체크하기.

문제 요구사항을 그대로 적은거 같은데 맞나요..??

SELECT 절에는 USER_ID 와 CATEGORY 와 SUM(AMOUNT) 가 필요해보입니다.
GROUP BY 절에는 USER_ID 로 그룹화해야 총 주문회수 COUNT(ORDER_ID) 를 할 수 있을거 같아요.

2단계
곧바로 필터링해야할 조건은 날짜 조건인거 같네요. 왜 그래야하는지는 사실 잘 모르겠어요.
총 주문 회수 조건은 GROUP BY 와 집계로 이루어질 테니까 남는 조건인 날짜가 WHERE 이겠지.. 싶은데
적합한 사고 방식인지 모르겠네요.
총 주문 회수 조건은, 특정 조건을 만족하는 대상의 목록이니까 WHERE IN 필터링이 필요하겠네요.

3단계
